# S2J Video Publisher - プラグイン仕様 (ドラフト)

採用・合意前の設計メモとして `docs_mod/` に置き、確定後は `docs/SPEC.md` に移行します。状態はドラフトです。記録日は2026-10-04です。

計算の正は [S2J Video Publisher Service のサービス仕様](https://github.com/stein2nd/s2j-video-publisher-service/blob/main/docs_mod/service_spec.md) です。本書は、WordPress 側の接続、台帳、cron、HTTP、管理画面を定義します。

## 概要

本プラグインは、自身が運営する YouTube チャンネルについて、動画ごとの公開期間を管理します。公開開始で限定公開 (`unlisted`)、公開終了で非公開 (`private`) にします。

スラッグは `s2j-video-publisher` です。ライセンスは GPL-3.0-or-later です。テキストドメインは `s2j-video-publisher` です。管理画面の見出しは「動画の公開期間」です。

初版のユーザーは、そのチャンネルの運営者です。OAuth クライアントはサイト設定であり、複数サイトに配る前提にはしません。KIS のサイトは、そのユーザーの一つです。

## 位置付け

| 層 | 名称 | 役割 |
| --- | --- | --- |
| 計算 | [s2j-video-publisher-service](https://github.com/stein2nd/s2j-video-publisher-service) | 公開期間の検証、次の操作、リクエスト材料。WordPress を知らない |
| 副作用 | **本プラグイン** | OAuth、台帳、cron、HTTP、監査後の resumable upload のセッション、管理画面 |

YouTube Studio の予約公開 (`status.publishAt`) は使いません。開始時刻は本プラグインのスケジュールが担当します。

## 目的

初版で、運営者が管理画面から次を終えることです。

* YouTube アカウントを、サイトに1つ接続する。
* Studio で予約公開なしの非公開にした動画の ID、タイトル、公開開始、公開終了を台帳に登録する。
* 開始時刻に `unlisted`、終了時刻に `private` に変える。
* 各行の状態、開始、終了、直近の失敗を一覧で見る。

YouTube API のコンプライアンス監査が通るまでは、ファイルのアップロードを出しません。監査後に、ブラウザから YouTube に直接送るアップロードを足します。

## 非目標 (初版)

* 公開開始の到達状態を `public` にすること。
* 公開終了で動画を削除すること。終了後は `private` のまま残す。
* 公開期間中に Studio で変えた公開状態を、分ごとに戻すこと。
* WordPress の投稿や固定ページの公開状態との連動。
* ライブ放送、プレミア公開、コミュニティ投稿、サムネイル、字幕、再生リスト。
* 複数チャンネルの同時接続。
* 動画ファイルを WordPress のディスクや PHP のメモリに載せること。
* WordPress.org への掲載。

## サービスとの境界

本プラグインは、サービスが返した操作だけを YouTube に送ります。

| 本プラグイン | サービス |
| --- | --- |
| 台帳の1行と「今」を渡す | 検証し、`none` / `set_unlisted` / `set_private` / `insert_private` を返す |
| 返った操作だけを HTTP で実行する | トークンと動画バイト列を、材料に含めない |
| ステータスとボディをサービスに戻す | 適用時刻、または失敗の結果レコードを返す |
| 結果を台帳に書く | 保存しない |

クライアント ID、クライアント・シークレット、リフレッシュ・トークンはサイト設定です。リポジトリにコミットしません。ログ、通知、画面には出しません。実行のたびにサービスには渡しません。サービスはトークンを知りません。

スコープは `https://www.googleapis.com/auth/youtube.upload` だけです。チャンネル全体の `youtube` スコープは要求しません。

## 接続

設定画面は「動画の公開期間 > 接続」です。操作できるのは `manage_options` を持つユーザーです。

画面に出すものは、次のとおりです。

* OAuth クライアント ID
* クライアント・シークレット (保存後は、値を再表示しない)
* 接続状態
* 「YouTube と接続」「再接続」「接続を解除」
* 監査完了 (下の「監査」)

「YouTube と接続」は、Google の OAuth 画面に遷移します。コールバックで認可コードをリフレッシュ・トークンに換え、サイト設定に保存します。アクセス・トークンは、期限までの一時保存にします。

OAuth 同意画面が Testing の間は、リフレッシュ・トークンが7日で失効します。無人のスケジュールには、同意画面を本番 (In production) にしたあとのトークンが必要です。これは YouTube のコンプライアンス監査とは別の手続きです。失効したら一覧の案内に出し、再接続を促します。

接続はサイトに1つです。

## 台帳

動画1行が、サービス仕様のレコードです。保存先は、専用テーブル `{$wpdb->prefix}s2j_video_publisher` とします。公開 URL を持つ投稿にはしません。

行が持つものは、次のとおりです。

| 項目 | 備考 |
| --- | --- |
| video_id | 未アップロードなら空 |
| title | - |
| description | 監査後のアップロードまで空でよい |
| publish_at | UTC の瞬間 |
| unpublish_at | UTC の瞬間 |
| phase | processing / scheduled / live / ended / failed |
| observed_privacy | private / unlisted / public / unknown |
| observed_processing | pending / processing / succeeded / failed / unknown |
| publish_applied_at | - |
| unpublish_applied_at | - |
| last_error | トークンは入れない |

画面の日付と時刻は、WordPress「設定 > 一般」のタイムゾーン、日付形式、時刻形式で出します。入力もそのタイムゾーンで受け、保存するとき UTC の瞬間にします。

同じ `video_id` の行は1つです。台帳から外しても、YouTube 上の動画は消しません。公開期間の途中で外すと、それ以降の終了処理は走りません。外す前に、その旨を確認します。

開始日時と終了日時は、対応する適用時刻が空の間だけ、変えられます。適用済みの時刻は表示のみです。

## 監査

2020-07-28以降に作られた未監査の API プロジェクトから `videos.insert` した動画は、非公開のままロックされます。監査が通るまで、アップロードは製品の機能にしません。

監査の前に作るのは、台帳とスケジュールです。運営者は YouTube Studio で、予約公開を付けずに非公開でアップロードした動画の ID を登録します。

「監査完了」は、接続画面の手動スイッチです。Google 側の状態を API で推測しません。オフの間、ファイル入力は出しません。登録項目は、動画 ID、タイトル、公開開始、公開終了です。

オンにしたあと、ブラウザから YouTube の resumable 先に直接送るアップロードを足します。セッション開始は本プラグインが OAuth 付きで行い、バイト列はブラウザから送ります。挿入時の公開状態は `private`、`publishAt` は付けません。処理が `succeeded` になってから、開始と終了のスケジュールに乗ります。

監査前の `videos.update` で、Studio から上げた非公開動画を `unlisted` と `private` に往復できるかは、動画1本で確認します。失敗した場合、開始と終了の自動化は監査完了まで保留します。確認用に、行ごとの「今すぐ実行」を出します。中身は、その1行について cron と同じ手順です。

## 画面

トップレベル・メニューの見出しは「動画の公開期間」です。

一覧の列は、タイトル、状態、開始、終了、直近のエラーです。動画 ID は、詳細と登録フォームに出します。

状態の表示は、次のとおりです。

| phase | 表示 |
| --- | --- |
| `processing` | 処理待ち。開始時刻を過ぎているときは「処理待ちのため、開始が遅れている」を添える |
| `scheduled` | 開始待ち |
| `live` | 限定公開中 |
| `ended` | 終了 |
| `failed` | 失敗 |

登録と編集のフォームは、監査前は動画 ID、タイトル、公開開始、公開終了です。開始は終了より前、タイトルは空でない、ことを保存前に見ます。同じ検査はサービスも行います。

## 実行

契機は1分ごとです。ライブラリは契機を知りません。`now` を受け取るだけです。

各回の手順は、次のとおりです。

1. 終了適用済みの行と、`phase` が `failed` の行は、API を呼ばない。
2. `phase` が `processing` の行だけ、`videos.list` で処理状況と公開状態を見る。公開期間中の行を毎分ポーリングしない。
3. 観測をレコードに書いてから、サービスに `now` と一緒に渡す。
4. 返った操作が `none` なら HTTP しない。
5. `set_unlisted` または `set_private` なら、`privacyStatus` だけを変える `videos.update` を送る。
6. 応答をサービスに戻し、適用時刻か失敗を台帳に書く。

失敗した行は、適用時刻を空のままにします。次分で同じ操作を返します。待避のための指数バックオフは持ちません。恒久的な失敗を `failed` にする判定はサービスです。

観測した公開状態が、次の操作の到達値とすでに同じなら、サービスが API なしで適用時刻を埋めます。本プラグインは、その結果を書きます。

## 実行の契機

ホストに OS の cron があるときは、1分間隔で WordPress を起動し、本プラグインの処理を走らせます。

OS の cron がないホストでは、WP-Cron を1分間隔で登録します。アクセスがない時間は遅れます。一覧に「アクセスがない間、開始と終了は遅れます」と出します。

どちらの契機にするかは、本番ホストが決まってから固定します。

## 監査後のアップロード

監査完了をオンにしたあと、登録フォームにファイル入力を足します。加えて、説明、カテゴリー、子ども向け宣言を受けます。これらは `videos.insert` のメタデータです。`publishAt` は含めません。公開状態は `private` です。

`status.containsSyntheticMedia` をボディに含めるかは、実装時の公式スキーマで決めます。子ども向け宣言の初期値も、そのとき決めます。

アップロードが終わると `video_id` が埋まり、`phase` は `processing` です。以降は、上のスケジュールに乗ります。

## 設計方針

[kis-wordpress エコシステム仕様](https://github.com/stein2nd/kis-wordpress/blob/main/docs_mod/specs.md) および [wp-plugin-spec](https://github.com/stein2nd/wp-plugin-spec) に従います。公開期間の判断はサービス側の純関数です。本プラグインはアダプタです。

フック登録、設定画面、テーブルの読み書き、`wp_remote_*`、cron、ブラウザへのアップロード・セッションは本プラグインに置きます。

| 借用する原則 | 本プラグインでの意味 |
| --- | --- |
| 依存の向きは外 → 内 | 画面、cron、HTTP がサービスを呼ぶ。サービスは WordPress を呼ばない |
| 内側はビジネスルール | 次の `privacyStatus` はサービス |
| 外側は詳細 | OAuth、台帳、cron、YouTube への HTTP |

Composer で `s2j/video-publisher-service` を require します。パッケージの参照元 (`VCS` か `path` か) は実装時に決めます。

無効化ではテーブルとスケジュールを残します。アンインストールでは、テーブルとサイト設定を消します。YouTube 上の動画は消しません。

## 実装順

1. 本ドラフトの合意。
2. Studio で非公開 (予約公開なし) にした動画1本に対し、監査前のプロジェクトから `videos.update` で `unlisted` と `private` を往復できるかを確認する。
3. プラグインの骨格、接続画面、台帳。「今すぐ実行」でその1本を往復する。
4. 1分ごとのスケジュールを、台帳の未了行につなぐ。
5. OAuth 同意画面を Production にし、リフレッシュ・トークンが7日で切れないことを確認する。
6. コンプライアンス監査のあと、ブラウザから YouTube に直接送る `videos.insert` を足す。

## 本ドラフトの提案

合意前の提案です。

* メニュー見出しは「動画の公開期間」。接続はそのサブメニュー。
* 台帳は専用テーブル `{$wpdb->prefix}s2j_video_publisher`。投稿タイプにはしない。
* 接続はサイトに1つ。スコープは `youtube.upload` のみ。
* 監査完了は手動スイッチ。オフの間、ファイル入力は出さない。
* 処理状況の確認は `processing` の行だけ。公開期間中の行は毎分見ない。
* 失敗の再試行は次分まで待つ。指数バックオフは持たない。
* 台帳から外しても、YouTube の動画は消さない。
* アンインストールでテーブルとサイト設定を消し、YouTube の動画は残す。
